# Agent Note: Widget 内容取舍与可读字号

Status: implemented

## 问题

用户反馈部分生成 widget 信息过多、字体过小。把框选范围视为必须逐项展示的内容，会使模型将整个选区压进有限画布。仅要求可读或增大字号不能解决这一倾向，还需要明确允许省略什么、保护什么，以及尺寸与显式内容要求冲突时如何处理。

## 决策

### 内容取舍与真实数据

[CORE](../../../../backend/src/design-system/core.ts)拥有内容取舍原则：普通选区限定候选来源，默认围绕用户目的选择一个重点和必要背景；显式点名与「全部」要求优先。省略次要统计、长描述、重复标签或低优先级条目，保留身份、单位、时间、关键状态和会改变含义的限定条件。列表依据已知优先级或时间选择，同等重要时保持来源顺序，节选说明策略由[正文优先且不自动显示覆盖提示](../../implemented/bug-fix/2026-10-09-widget-content-without-coverage-labels.md)调整，默认不添加覆盖提示。无法在明确尺寸内完整呈现显式要求时，说明冲突并请用户选择减少内容或增大尺寸。

这是一项展示策略，不修改源网页。稳定的字段取舍可以写入生成代码，随数据变化的记录选择、数量和缺值处理必须在每次提取或渲染时应用。运行时刷新没有模型参与，不能把自由改写的捕获摘要或选中记录硬编码为长期业务文本；优先使用可更新的标题、字段与原文短段。

### 图形、图像与可读性

能清楚表达主信息的真实图形或相关来源图片优先成为视觉主体，必要文字保留名称、关键值、单位和背景。趋势需要真实序列，进度需要真实目标；没有合适数据或素材、图形在实际尺寸下难辨、或用户要求不用图时，采用文字布局。图片提取、data.json 传递、失败降级及三文件协议保持原有机制。

[tokens](../../../../backend/src/design-system/tokens.ts)单点拥有各尺寸字号；body 承担需要阅读的内容，caption 仅承担简短辅助标签。拥挤时先减少非必需内容、条目和装饰，再调整构图；保留传达主信息的图形或图像，必要时简化其细节，不通过缩字或整体缩放增加信息量。用户明确的字体与风格偏好可以覆盖默认值。

[模式](../../../../backend/src/design-system/patterns/index.ts)提供各尺寸的柔性构图起点，列表依据当前标题换行和可用高度选择容量。[brief](../../../../backend/src/agent/brief.ts)、组件与评审引用统一原则；截图自评检查主信息、正文和留白，最终回复简述保留重点与主要省略类别。这些都是生成指引，不新增任意 HTML 的运行时字号拒绝规则。

### 归属与范围

本决策部分调整[简洁图文设计决策](../feature/2026-10-06-minimal-widget-design-style.md)对请求内容与视觉主体的默认处理。该记录的渐进加载、设计目录、图片处理及替代方案仍有独立价值，保持活跃并互相链接；没有完全取代、归档或删除的笔记。[静态 widget 决策](../feature/2026-09-30-static-ios-widget-artifacts.md)继续拥有尺寸、静态截图与交付规则，使用及扩展说明由 [Design System 文档](../../../../docs/design-system.md)拥有。

不增加客户端配置、固定模板、独立评审模型或旧产物自动迁移。密度建议仍可依据真实生成证据单独调整，不预建配置或迁移接口。

[按内容用图决策](2026-10-08-contextual-image-priority.md)细化依据页面内容与展示目的选择图片的通用指引，并区分视觉选图与图片实际读取；本记录的内容取舍与可读字号决策继续有效。

[按可用空间组织列表](2026-10-08-widget-space-utilization.md)针对仍有相关候选时过早截断与大块空白，补充容量判断和预览调整；本记录的可读字号与防过载原则继续有效。

## 曾考虑的替代方案

**只提高默认字号。** 能改善部分结果，但不解决全量展示倾向；密集页面可能溢出、裁剪或促使模型自行缩字，需要同时明确内容取舍。

**只在 brief 增加一句「少放信息」。** 改动小，但与模式和评审中的全量要求冲突，缺少显式内容与运行时数据保护。统一原则并同步相关指引能够消除这些矛盾。

**强制同一条目上限或运行时字号检查。** 标题长度、图文占比和完整展示要求不同，统一截断可能删除关键信息。采用尺寸建议和真实生成验收；若模型持续忽略规则，再评估可观察、可解释的自动检查。

## 验证

- `npm test -- src/agent/brief.test.ts src/design-system/catalog.test.ts`：5 项通过；`npm run test:agent`：5 项真实 SDK 测试通过。`npm run verify-design-system`、`npm run typecheck`、`npm run verify-docs`、`npm run verify-notes` 和 `git diff --check` 通过。
- [真实模型检查](../../../../test-cli/design-checks.mjs)使用本地 Wrangler、gpt-6.1-sol 和 Browser Run，按案例完成 11 个场景、12 轮生成或回复。三档密集选区均实际省略次要内容：small 保留供水数值与限定条件，middle 显示两条完整长标题并标明节选，large 保留公告状态与通行限制。原尺寸截图经过目视检查，正文及辅助标签可读，无溢出或遮挡。
- 替换来源后重新执行生成的提取与渲染：供水数值、零值、缺值及单位正确；列表首条随新记录更新，覆盖提示从 `2 / 8` 变为 `2 / 5`、`1 / 1`；公告状态随来源更新。变短和空数据均通过预览，未沿用捕获业务值。
- 六篇文章标题与栏目完整保留；明显超量的小尺寸请求说明无法以可读字号完整展示，提供减少内容或扩大尺寸的选择，没有交付缩字或删减的产物。只要求步行记录主题时生成真实序列图；商品场景自动选图，坏图时保留名称和价格，后续深色不用图偏好得到遵守。缺历史和 canvas-only 场景没有虚构数据。
- 证据保存在本地 `downloads/design-check-VkFUXf`、`downloads/design-check-euDOUX`、`downloads/design-check-fyRKmD`，包含源页面、事件、产物、截图、提取数据、回复及模型 usage。前两次整体命令分别因测试截图超出捕获预算、节选断言漏认分数形式而失败，不计为整轮通过。检查脚本复用现有截图合成器，并识别分数形式；`DESIGN_CASES=long-list,dense-metrics npm run e2e:design` 最终退出 0，其余案例的成功结果分别保留在前两个目录。
- 首轮 brief 从 12,501 增至 14,431 UTF-8 字节；按每四字符一个 token 粗估为 3,124 → 3,607，增量 483。六种模式、三档尺寸、含案例的设计上下文由 5,490–6,502 增至 6,162–7,253 字节，粗估 1,373–1,626 → 1,541–1,814 tokens。原文及测量保存在 `downloads/widget-density/context-{before,after,size}.json`；这是 brief 与工具结果体积，不包含工具 schema、源页面或截图，不能视为实际请求 usage。实际 usage 由每次真实模型运行独立记录。

## 后果

正文增大会减少可展示条数，这是以信息总量换取可读性的取舍。模型仍可能误判重点或过度删减；显式内容保护、真实页面案例与简短取舍说明降低风险，不能保证所有网页都正确。图形或图像必须传达主信息，不能靠装饰弱化关键数值；不可提取或加载失败时需保留可读文字。

提示词与 tokens 更新只影响后续生成或修改，已有 widget 不会自动改变。本次未部署生产环境；Chromium 参考画布验证不能替代 iOS 真机阅读与 WKWebView 验证。
