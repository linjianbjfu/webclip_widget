# Agent Note: Widget 按信息关系分组与分配横向空间

Status: implemented

## 问题

Yahoo session 441121c2-8f08-4cba-83c9-f4898b0552b7 在 344×360 画布显示六场比赛。每场使用 `minmax(0,1fr) 100px minmax(0,1fr)`，两队靠外侧、比分占固定中央列；联赛和状态再以 space-between 分到两端。队名、比分和状态要跨多个位置才能关联，中间形成重复空带，两侧图标和文字却拥挤。增加图标不能修复这种分组问题。

参考图 app-usage 将图标、名称和时长聚成一个实体单元；paired-routines 与 current-next 让同级事项各自拥有明确的阅读区域。关键是相关内容的距离小于组间距离，而非统一居中、对称或强行铺满整行。现行 list/row 指引强调对齐、条数及可读字号，但未明确如何识别和重组横向空带。

该 session 还将主比分节点的 textContent 作为比分，包含其中的点球 span，导致 TOR 的 3 与 1 拼成 31，VGK 的 4 与 2 拼成 42。保存的 source.html 明确区分这两层数字，布局验证需要同时核对字段归属。

## 决策

### 通用分组规则

CORE、list、row/group、REVIEW 和已有参考分析规定：先确定一个可独立阅读的信息组，将识别图、名称、数值及必要状态放在组内；同类组共享对齐线，组内间距小于组间间距。布局评审检查长距离关联、重复中间空带、两侧拥挤及非必要的镜像排列，避免把所有行都套成左右贴边的标签值结构。

依据内容长度和可用宽度选择紧凑单列、双列或其他组合。短名称、多字段的同级记录可使用双列；长标题、长名称、窄画布或明确全量要求不强制双列。不给所有列表增加统一模板或空白比例门禁。宽度应服务实际内容，不以固定大空列承担对齐。

保持白底、克制的灰色辅助信息及有意义的分区。用细分隔线或留白分开组，不为每个字段加边框或背景；图标和背景继续遵循已有来源、预算与失败处理。先确定阅读顺序，再评估装饰；不靠补背景填空带，不缩字号或减少必要字段来取得整齐外观。

### Yahoo 对照与字段核对

该 case 的独立新产物采用两列比赛组，按来源顺序从左到右、从上到下排列。每场顶部集中显示联赛与状态，两队在其下上下排列，每行队徽、队名、比分对应；排名贴近队名，系列赛或点球说明留在所属比赛内。取消横跨整张 widget 的大比分列和右侧镜像队名。

提取指引要求分开含义不同的字段，检查子节点与直接文本，避免父节点 textContent 拼接；没有 Yahoo 专属运行时解析器。原 session 保留，新产物按当前内容测量容量，不固定六场。双列以来源顺序排列完整记录，并按当前字段宽度和高度决定容量。

### 归属

[设计文档](../../../../docs/design-system.md)拥有布局使用规则，[brief](../../../../backend/src/agent/brief.ts)拥有嵌套数值提取要求。列宽与换行在每次渲染时依据当前名称重新判断，替换名称回放用于防止捕获时的短标签决定固定列宽。

本决策补充[白底与层次](../feature/2026-10-09-white-layered-widget-style.md)、[条目图标与背景](../feature/2026-10-09-content-icons-and-backgrounds.md)和[空间利用](2026-10-08-widget-space-utilization.md)。三篇继续拥有视觉素材与容量取舍，保持活跃并互相链接；无归档或删除。

## 曾考虑的替代方案

**缩小中央比分列、保持原来的左右对称排列。** 可以回收部分宽度，但联赛、状态与球队仍散在两侧，多字段记录的阅读关系没有改善。

**用背景图片填补中间空白。** 只能增加视觉重量，无法让数值更靠近它所属的实体，还可能干扰正文。

**所有列表强制两列，或固定每屏六场。** 短比赛组适合两列，但长标题与显式全量要求可能更适合单列；条数和结构必须由内容决定。

## 后果

组内关联清楚的短记录可以并列，长名称与窄尺寸仍可能需要单列。布局不以对称、统一列数或空白比例为目标；文字与字段保留由机械检查约束，视觉关系仍需目视评审。真实生成出现过固定列宽裁切，说明短数据预览通过不能替代更新回放。

[图片格式协商与视觉层级](2026-10-09-image-format-and-visual-priority.md)验证该 CDN 的黑底来自默认 JPEG 响应，并规定 Accept、reload 与图像主导时的布局权重。本记录继续拥有组内字段关联，不抠图或引入新素材来源；CORS 与读取限制仍存在。已有下载不自动迁移，未部署生产环境，未验证 iOS 真机。
