# Agent Note: Widget 按可用空间组织列表内容

Status: implemented

## 问题

session 28849f0a-1901-489c-a676-28b0176ab4cf 的大号市场热点 widget 仅展示十条来源记录中的五条，底部留下明显空白。extra.js 和 widget.html 都使用 slice(0,5)，提取阶段已丢弃后五条。ol 的 flex:1 只让列表容器占满剩余高度，固定行高和 gap 的列表项仍集中在顶部。

在项目 344×360 参考画布上，原产物最后一条底边为 y=255，距画布底部 105px，扣除 20px 底部 padding 仍有 85px。保持正文 15px、行高 21px、行距 12px，七条最后底边为 y=321；移除独占一行的装饰短线后，八条底边为 y=338，均无溢出。原始 session 保持不变；测量及只用于评审的变体保存在本机 downloads/widget-space-review，使用保存的 v2 结构快照和全部十条真实标题。

CORE、list 模式和 REVIEW 主要指导拥挤时删减，大号列表的「从 4–6 条开始」容易成为固定上限。虽然声明条数不是配额，缺少预览后空间不足与空间富余两个方向的调整要求。现有技术预览检查溢出、加载等错误，不能把 validation passed 当成空间利用合理。

## 决策

### 按内容与实际空间调整

CORE 和 REVIEW 要求：保留必要留白，同时检查内容是否无意中挤在一角。来源还有同等相关记录、可用区域能放下完整条目时，应恢复更多记录；不要以固定建议条数提前停止。没有更多相关内容时，根据主题调整主体位置、字号层级或图像/图表尺寸，允许有意的留白，不补无关信息或装饰。

list 模式的尺寸指引依据可用高度、正文行高、标题换行与图文占比判断容量，不提供默认固定条数。compact heading 优先于独占空间的装饰。保持现有字号、正文可读性、来源顺序、显式字段保护和真实数据原则；不将本案例的七条或八条设为全局上限。

纯文本列表提取应保留与选区相关、数量有界且足够评估布局的候选记录，避免提取与渲染重复按同一固定展示条数裁切。展示数量由渲染端依据当前内容和空间决定，不为覆盖提示预留空间；该策略由[正文优先且不自动显示覆盖提示](../../implemented/bug-fix/2026-10-09-widget-content-without-coverage-labels.md)拥有。需要随标题长度适配时，可在 renderWidget 内同步测量完整行并选择能容纳的前缀；不靠缩字、截断主标题、隐藏溢出或后台定时任务。图片列表仍遵守已有图片数量和字节预算，不为补齐空间扩大图片请求。

### 提示词与验证

同步 CORE、list、REVIEW、brief 的预览收尾指令及 Design System 文档。模型需在 preview_widget 返回截图后同时处理拥挤和无意义空白；纯技术检查通过不能结束明显未完成的布局。没有新增预览工具、统一运行时组件、全局空白占比门禁或配置参数。

[space-list 与 space-limited](../../../../test-cli/design-space-cases.mjs)通过现有 e2e:design 入口调用真实模型，验证十条标题、变长、少量与空数据，以及明确只展示五条。浏览器测量标题边界、字号、展示数量与非请求的覆盖提示；独立负例证明过早截断、缩字、裁切和自动覆盖提示不能通过这些场景检查。

本记录细化[内容取舍与可读字号](../../implemented/bug-fix/2026-10-08-widget-content-density.md)中的容量判断，保留其防止过载和保护明确要求的决策。[简洁图文设计](../../implemented/feature/2026-10-06-minimal-widget-design-style.md)的设计分层和图片策略仍有效，两篇继续活跃，无归档或删除。布局指导与取舍由 Design System 拥有，brief 只同步预览行动，避免重复整段规则。

## 曾考虑的替代方案

**只把当前 session 的五条改为八条。** 评审原型证明八条在当前文本下可行，但无法改善后续生成或适应更长标题，不能解决通用需求。

**用 space-between 或增大行距把五条铺满。** 可平衡视觉，但本例仍有同等相关记录没有显示；应先评估恢复条目。来源仅有少量记录时，适度调整间距和主体位置仍合理。

**统一要求填满画布或增加全局空白比例失败规则。** 主指标、图文和少数据布局可能需要较多留白；一个比例不能表达内容质量。先采用内容相关的指引和有明确候选记录的场景验证。

**提高大号默认条数。** 更换数字仍会锚定固定数量，遇到换行标题和图片列表可能重新造成拥挤；推荐按实际内容容量决定。

## 后果

恢复记录可能增加阅读负担，因此只增加同等相关且可完整呈现的内容，不追求每个像素都放信息。同步布局测量保持有界，不建立通用布局引擎。场景中的原始十条与底部余量检查只约束该夹具，不成为主指标、少数据或图片布局的通用规则。

提示词不能保证每次生成都成功，小尺寸回归中的数字行溢出说明技术预览和截图检查仍不可省略。若空间利用持续不稳定，再依据失败证据评估具体诊断，不预设全局空白比例门禁。

规则作用于后续生成/修改，不批量重写历史下载。本次额外用用户原捕获生成了一份独立产物，方便比较；原产物保持不变。本次未部署，未验证原站实时数据或 iOS 真机换行。
