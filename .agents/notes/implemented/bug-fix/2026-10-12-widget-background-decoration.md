# Agent Note: 背景使用来源素材并省略自绘几何装饰

Status: implemented

## 问题

用户提供的 NBA widget 截图右上角出现浅黄色圆圈与十字线组合。图形虽然透明度低，却像占位符，不能改善内容识别或视觉质量。CORE 主动建议 simple CSS/SVG motif，review 也鼓励主题层；现有背景检查只证明图层存在且足够淡，不能证明它美观。

## 决策

CORE 与 review 规定不生成用圆圈、十字、弧线等简单形状拼出的装饰性主题水印，不以低透明度作为采用它们的理由。优先使用与当前内容有关、适合构图的来源图片作为局部淡背景；没有合适素材时使用白底、浅灰语义分区和必要分隔线。保留真实数据图表、承担识别作用的前景图标以及图片渐隐遮罩。

设计文档和背景场景使用同一规则。比分场景请求局部来源图片背景，素材是可重复生成的透明盾牌图标；背景检查要求图片来自当前来源、正常解码、有定位图层且独立淡化，拒绝圆圈加十字代替来源图片，也拒绝包含正文的父层一起淡化。换图、换序、缺图和坏图继续重放。该检查不以固定透明度判定美感，实际截图仍需目视检查，不通过禁用所有 SVG 或圆形元素误伤图表和队徽。

本决策部分取代[列表识别图标与低对比度主题背景](../feature/2026-10-09-content-icons-and-backgrounds.md)和[白底、浅灰分区与局部背景图](../feature/2026-10-09-white-layered-widget-style.md)对简单 CSS/SVG 背景的许可。两篇继续拥有图标提取预算、来源图片、白底分区及降级理由，保持活跃，无归档或删除。规则作用于后续生成和修改，不自动改写已有下载产物。

## 曾考虑的替代方案

**只禁止圆圈加十字。** 模型仍可能改画同类弧线、圆环或网格来填角落，不能解决装饰素材质量问题。

**取消所有背景图片。** 会丢失用户已明确喜欢的局部淡背景效果，超出此次反馈范围。

## 后果

无合适来源图片的页面更简洁，这是有意的取舍。模型输出有随机性，截图检查不能保证所有后续页面均符合审美；没有增加按 DOM 标签或形状全局封禁的运行时规则。图片提取与显示数量政策不变。未部署，未验证 iOS 真机。
