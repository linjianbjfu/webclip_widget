# Agent Note: Widget 将节选提示空间用于正文

Status: implemented

## 问题

session f2a726b6-717e-4ee6-aaad-edfd5cb7b7ff 提取到了十条市场热点，widget 却显示九条和「精选前 9 条 · 共 10 条」。在 344×360 的 Chromium 画布实测，底栏本身高 25px，加上上边距共占 35px；列表可用高度 247px。仅在内存中隐藏底栏并重新渲染，列表高度增至 282px，十条完整显示，最后一行底边为 328px，正文仍为 15px、行高 21px。原下载文件没有修改。

这不是提取缺失。CORE 要求标明节选或数量，list 模式要求提前预留覆盖提示空间，REVIEW 和回归测试又要求计数正确，模型按这些规则生成了占空间的底栏。用户希望空间用于相关正文，放不下时也不显示展示数量或来源总数提示。

## 决策

Design System 的 CORE 禁止默认生成节选、已展示数、总数、剩余数和「全部 N 条」提示，适用于底部、标题等所有位置。list 模式不给覆盖提示预留空间；REVIEW 检查非请求的提示是否挤占正文。来源本身的业务数量、排名、必要状态，以及用户明确要求的覆盖信息仍可显示。

列表先移除冗余标签和装饰，合理安排标题、内边距和行距，在可读正文、完整标题、必要留白和来源顺序的约束下，增加能放下的同等相关条目。容量不足时显示完整的有序前缀，不添加截取说明。字号遵循现有 tokens 与用户偏好，不增加自动缩字、整体缩放或全局固定条数；显式「全部」和指定条数要求仍受保护。

[设计文档](../../../../docs/design-system.md)拥有当前使用约束。[列表场景](../../../../test-cli/design-space-cases.mjs)和 [long-list](../../../../test-cli/design-checks.mjs)验证容量与数据刷新，并拒绝自动覆盖提示。断言只用于已知来源的测试场景，先排除原始业务文本，避免把价格、进度或排名当成展示计数；不是生产 HTML 后处理器或全局数字过滤规则。

本决策部分取代[内容取舍与可读字号](2026-10-08-widget-content-density.md)和[按可用空间组织列表](2026-10-08-widget-space-utilization.md)的强制覆盖提示要求。该要求原本用于避免把子集误认为全量，但在紧凑 widget 中会挤占正文，且用户不需要它。两篇的候选提取、动态容量、可读性及显式要求保护仍有效，[按内容用图](2026-10-08-contextual-image-priority.md)也保留独立价值；三篇继续活跃并互相链接，无归档或删除。历史生成验证中的计数结果仍作为当时的证据保留。

## 曾考虑的替代方案

**只修改当前下载中的 footer。** 实测能恢复第十条，但后续生成仍会遵循强制计数的提示词，无法满足通用需求。

**把计数压缩成 N/M 或挪到标题旁。** 仍然展示用户不需要的截取说明，且继续消耗正文或标题空间。

**降低字号以保留底栏并增加条目。** 此例无需缩字即可显示十条；为计数牺牲正文可读性没有必要。

## 后果

省略计数后，读者不能从 widget 得知还有多少条记录，这是为正文空间与简洁呈现接受的取舍；仍不能把子集包装为完整统计。用户明确需要覆盖范围时按其请求显示，不恢复通用底栏。

规则作用于后续生成和修改，历史 widget 不自动重写；本次原 session 保持不变。提示词不能保证每次生成都合规，截图及数据更新检查仍有必要。本次没有部署，未验证雪球实时页面或 iOS 真机。
