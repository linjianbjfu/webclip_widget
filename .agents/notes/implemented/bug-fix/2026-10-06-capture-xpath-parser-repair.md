# Agent Note: 捕获 XPath 校验兼容 HTML 解析修复

Status: implemented

## 问题

腾讯科技页的运行时 DOM 包含嵌套 a 链接。HTML 解析器重新解析捕获字符串时会拆开、复制或移动锚点，导致完整新闻容器的 outerHTML 改变。把实时元素与捕获元素逐字比较会误报“XPath 与捕获 HTML 不一致”，延长 load 等待不能解决。普通 svg/g/path XPath 又缺少命名空间，可能零匹配。

页面调查显示，具体卡片是否受影响取决于当次内容及实际吸附节点；用户提供的新闻列表截图不能确定选中的元素。完整卡片、列表和共同父容器均属于验证范围。

## 决策

在克隆文档中用不与原页面属性冲突的临时标记追踪选区，不修改实时网页。解析后标记必须唯一对应一个节点；检查选区文本（归一化空白）、链接目标与图片引用保留，允许内部结构修复及相同链接的复制。标记缺失、多重映射或内容移出选区都明确拒绝，提示区域编号、路径及选择完整父区块，不猜测第一个匹配或自动扩大范围。

删除映射标记后输出规范化的 source.html，再解析一次，确认 XPath 唯一定位且规范化节点结构稳定。这里比较的是两次解析后的节点，不要求实时节点与捕获节点的 outerHTML 相等。HTML/SVG 路径处理命名空间、重复 id 和包含引号的 id。

region.xpath 指向最终捕获 HTML；可选 sourceXPath 保存不同的实时路径。server 保留并验证该字段，prompt 区分两条路径的用途，生成 extra.js 时仍要求选择稳定锚点。旧 capture v1 无需新增字段；已有 debug 文件不回写。线上字段和限额由[协议](../../../../docs/protocol.md#capture区域与图片)拥有。

截图前后的 source、实时选区 fingerprint 和区域位置检查继续发现真实变化。诊断在 UI/CLI 中仅显示消息首行，排除 Puppeteer 的 pptr:evaluate 调用位置。使用说明见[CLI 文档](../../../../docs/test-cli.md#框选页面内容并生成-widget)。

本记录部分替代[多区域捕获](../feature/2026-10-05-region-capture-multimodal-widget.md)的定位判据；其输入、拼图和存储理由继续有效，两篇保持活跃。

## 曾考虑的替代方案

**取消 outerHTML 比较，只检查 XPath 命中数量。** 可能接受已移位到其他元素的路径，或忽略内容移出选区，因此保留节点映射及内容检查。

**延长等待或重试。** 嵌套链接解析修复和 SVG 命名空间缺失是确定性问题，等待不能消除。

**改写真实页面，使嵌套链接变为普通容器。** 会改变交互、布局及截图来源，因此仅规范化克隆文档。

**取任意匹配或更大父节点。** 会改变用户范围，因此拆分时要求用户选择完整父卡片。

## 后果

完整卡片和列表可容忍内部 HTML 修复，而无法完整表达为 HTML 的选区仍需重新选择。捕获与实时层级可能不同，sourceXPath 防止模型混淆定位用途，但不保证未来页面结构不变。iframe 和 Shadow DOM 内部仍不支持。

腾讯科技页实测中，新闻卡片、列表与 #channel-feed-area 均通过新的快照校验，包含 outerHTML 已改变的区域。实际截图流程仍被原有动态变化检查拒绝：捕获期间广告 script 被删除，加载更多状态从“加载更多”变为“加载中...”。这不是 XPath 映射失败；该真实网页的完整截图发送流程未验证通过。若需允许选区外的这些变化，应单独评估缩小稳定性检查范围，而不能用本修复静默放宽。

## 验证

- 浏览器回归用 DOM API 构建嵌套链接，旧实现复现原异常；修复后卡片/列表内容完整，移动后的 XPath 对应正确。拆分、内容丢失与节点丢失均被拒绝。
- 9 项相关浏览器测试通过，覆盖真实拖框、错误展示、重新选择、拼图预览/确认、sourceXPath 输出、SVG/id、临时属性冲突和实时 DOM 不变。
- 8 项 server schema/brief/capture prompt 测试、18 项 CLI 测试及 TypeScript 检查通过。没有调用真实模型生成 widget。
- capture brief 按仓库 UTF-8 字节数除以 2 的保守口径估计从 564 增至 639 token（增加 75）；这不是供应商的实际分词计数。
