# Agent Note: 白底、浅灰分区与局部背景图的 Widget 风格

Status: implemented

## 问题

用户提供六张参考图，希望 widget 以白色为主背景，通过部分浅灰底区域、背景图或局部淡背景图增加视觉层次。现有浅色 surface 为 #FAFAF8，没有独立的分区底色；CORE 强调少容器，image 组件只笼统要求背景上的文字对比度，缺少如何组合白底、信息组与图片的具体指导。模型容易生成只有文字与留白的单层画面。

参考图的共性是清晰的主标题或主数值、安静的白色画布、少量有意义的分区，以及围绕主题安排的图标或图片：会议卡片把分类和参与者放入浅灰底区域，日程卡片用浅灰底区分当前事项，药品卡片在右侧叠加淡背景形状，停车卡片把图片集中在上部并向正文区域淡出。这些是可复用的视觉关系，不是每个 widget 都必须采用的模板。

## 决策

### 白色画布与语义分区

[tokens](../../../../backend/src/design-system/tokens.ts)提供白色浅色主背景、surfaceMuted 明暗分区底色和 radius.group。group 组件用平面浅灰区域组织相关辅助字段或当前事项，也允许同级内容共享白底并用留白或细线分隔。模型按内容选择，不给每行套卡片，不层层嵌套，不把分区数量当成配额；密集列表或单一信息可以保持白底。深色主题和用户明确配色优先级保留。

CORE 保留可读性与正文容量约束，同时鼓励有意义的信息分区。六种既有模式均能发现 group 规范，freeform 说明主信息加辅助区与当前/下一项并列等组合；没有增加业务题材专属模式或固定 HTML 模板。

### 图片层次与降级

image 组件支持主体、行内识别图及整个或局部背景。背景可以放在顶部、边缘或文字稀疏一侧，通过裁切、图片自身的透明度或向底色渐隐的独立遮罩保护正文。文字保持不透明；承担识别任务的前景图保留足够细节，装饰不挤占必要内容。

栅格背景采用 img 放在正文后方的定位层，可以定位图片本身或独立容器，继续进入已有的图片解码等待和失败检查。背景与当前记录同步更新，缺失或损坏时移除图片层，保留白底或灰底及文字。CSS background-image 不作为额外加载通道。

图片来源继续使用原有 img 提取、base64 与已提供静态素材机制，不新增源网页 CSS 背景采集、图片搜索/生成、远程地图服务或客户端协议。没有素材时允许文字、分区和简单 CSS/SVG 主题图形；地图、人物和商品必须与实际内容对应。参考图不能裁成业务素材，捕获截图不能充当带有陈旧数值的背景。

### 参考与上下文

六张用户参考图保存在 design/widget-style，具体链接及使用说明由[设计文档](../../../../docs/design-system.md#白底分区与图片层次)拥有。examples 保存短构图分析，适用模式按需返回最多两份，不在每轮附加六张位图。参考中的操作按钮和外部展示框不属于静态 widget。

本决策细化[简洁图文风格](2026-10-06-minimal-widget-design-style.md)的视觉默认值，并补充[按内容用图](../bug-fix/2026-10-08-contextual-image-priority.md)的图片角色；两篇的渐进加载、素材来源与提取边界继续有效，保持活跃并互相链接，无归档或删除。[空间利用](../bug-fix/2026-10-08-widget-space-utilization.md)与[正文优先](../bug-fix/2026-10-09-widget-content-without-coverage-labels.md)继续约束分区和图片的空间成本。

## 曾考虑的替代方案

**只把默认背景改成白色。** 能改变底色，但缺少语义分区和图像层次，不能充分表达参考图的风格。

**每个 widget 都加入灰色卡片和背景图。** 容易把装饰变成配额，挤占新闻列表正文，也会在没有合适图片时诱导无关素材。推荐根据内容和可用空间选择。

**仅允许独立前景图片。** 复用现有图片能力最直接，但无法满足局部淡背景的需求。采用独立 img 背景层可复用已有解码等待和逐图降级，同时支持目标效果。

**每轮附上全部参考图。** 视觉表达直接，但增加上下文成本并可能引导照搬按钮、示例人物和业务内容。先使用持久参考与简短分析，若真实生成持续偏离，再评估按需图片上下文。

## 后果

灰色分区会消耗额外 padding，背景图可能干扰正文或损失识别细节，因此颜色、图层与数据更新使用确定性检查，背景和文字的视觉关系仍需原尺寸截图判断。不用统一灰色比例、透明度或审美分数替代内容判断，不通过缩小正文增加装饰。

网页图片可见不代表能够读取，base64 继续受原有 CORS、CSP 和预算限制；缺图时布局必须成立。参考图尺寸较大，不能照抄比例；真实模型输出存在变化，单次示例不能保证所有页面符合风格。

新规则作用于后续生成和用户请求修改，已有 widget 不自动迁移。本次未部署，未验证第三方实时页面或 iOS 真机。
