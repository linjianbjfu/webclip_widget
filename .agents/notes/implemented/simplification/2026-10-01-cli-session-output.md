# Agent Note: CLI 按会话覆盖本地产物

Status: implemented

## 问题

按 turnId 分目录会使同一会话的最新 widget 路径不断变化。用户需要固定保存到 downloads/sessionId：目录不存在时创建，存在时覆盖产物。

## 决策

CLI 使用 `downloads/<sessionId>/`，覆盖 extra.js、widget.html、meta.json。保存函数不接收 turnId；turnId 仍用于筛选当前请求的完成事件。同一会话的多轮结果使用同一路径，包括本地修改过的三个产物文件。

整个 bundle 通过文件集合、UTF-8 字节数、哈希和 metadata 校验后，先写入临时目录，再逐文件重命名替换。会话级目录锁阻止两个保存过程交错写入。每个文件替换完整内容；客户端生成的 data.json、其他文件和原有旧轮次子目录保留，不自动迁移或清理。

[静态 widget 决策](../feature/2026-09-30-static-ios-widget-artifacts.md)的每轮本地目录选择由本决策替代；尺寸、提取、服务端执行及传输理由继续有效，原笔记保持活跃并同步事实，没有完整取代或归档的笔记。

## 曾考虑的替代方案

**保留每轮目录。** 能保留历史产物，但用户明确选择固定会话目录并覆盖。

**替换整个会话目录。** 可把 bundle 当作目录整体发布，但会误删同目录的客户端 data.json 或其他文件，因此只替换三个产物。

## 验证

`npm run test:cli` 的 5 项测试通过，包含首次创建、全部三文件覆盖、保留运行时数据和旧子目录、非法 bundle 拒绝覆盖、文件系统失败后的暂存及锁清理。真实 CLI 子进程验证 prompt、连续 chat、实时 events 的打印路径和最终文件内容；错误 turnId、损坏数据或提前断线不能覆盖当前结果。文档、Notes 和 diff 门禁通过。

## 后果

同一会话的最新产物有固定访问路径，本地不再自动保留每轮历史。三个文件逐个替换，替换中途发生 IO 故障可能留下跨版本组合；CLI 会报错，不宣称保存成功。旧轮次目录不自动迁移或删除。
